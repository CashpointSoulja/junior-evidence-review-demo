# Assumed weekly analyst workflow

**Status: assumption.** This is a working model to design against, built from Junior's public descriptions of call types and from common commercial due-diligence practice. It has not been validated with Junior customers. Discovery questions to test each step are in [discovery-plan.md](discovery-plan.md).

| Day | Step | Where Evidence Review fits |
|---|---|---|
| Mon | Scope questions with VP; book 3–6 expert calls through networks | Diligence questions become the gap queue's rows |
| Mon–Wed | Run calls; Junior records, transcribes and summarises | Quotes arrive as structured records (here: synthetic seed) |
| Wed | Draft synthesis: 8–15 claims across the questions | Claims link to quote IDs |
| Wed–Thu | Self-review before sending to VP | **Checks, comparison table, manual review, edits with lineage** |
| Thu | Remaining gaps → next calls | **Gap queue → template-based follow-up guide** |
| Thu–Fri | VP review, IC pack or client readout | **Handoff gate, approval, export with source links** |
| Fri | Share outside the deal team (sometimes) | **Selected-identifier redaction with preview and warning** |

Assumed pain points to test:

1. Self-review is skipped under time pressure, or covers only headline claims.
2. Cohort differences are escalated as contradictions (noise), or real contradictions are missed.
3. Follow-up questions written in a hurry lead the expert.
4. The VP cannot tell which claims the analyst actually checked.
